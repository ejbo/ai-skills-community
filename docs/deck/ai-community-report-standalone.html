社区里唯一一个直接进到别人生产流程里的模块

功能亮点 用户看到什么

  • 一行命令装进项目。skills install <名称> 默认装到当前项目，一次可装多个；合集包一条命令装齐一整套。
  • 三档可见性 + 逐人审批。受限 Skill 能被搜到但要作者点头；批准、拒绝、随时收回，每一步都有通知。
  • 不用装就能先试。详情页直接和"已经装上这个 Skill 的模型"对话，切走页面也不打断生成。
  • 装了到底有什么不一样。同一个任务、同一个模型跑两遍（带 / 不带 Skill），把两份真实输出交给 AI 写成对比报告。
  • Remix：在别人的基础上改，编辑器里有逐行 diff，发布后自动记住来源，原作者的被 Remix 数 +1。

技术亮点 工程上难在哪

  • 一个权限判定，六个出口复用。访问判定压成一个纯函数（owner / 公开 / 已授权 / 需申请 / 拒绝……七种结果），网页会话与 CLI 令牌先收敛成同一个"身份"再进它；下载、元信息、存储代理、文件浏览、更新检查、试用对话全走这一处。"网页拦住了、CLI 没拦住"是这类平台最典型的漏洞。拒绝一律返回 404 而不是 403，连"这个私有 Skill 存在"都不暴露。
  • 下载配额与参数绕过。按滚动 24 小时窗口对下载流水计数；只信任地址里 install / update 两个来源值，其余按浏览器标识回落 —— 否则手拼一个"试用"参数就能白嫖配额。绕开主路径直接取包的那条路也被堵上并同样计数。
  • 撤权即断更、更新可回滚。CLI 批量检查更新时复用同一套判定，授权被收回的 Skill 直接当"不存在"：既不提示更新，也不暴露它还在。客户端更新前先把目录改名备份，装失败自动回滚，绝不留下装了一半的 Skill。
  • 内网没有 npm 源，CLI 自己做分发。安装包挂在站点上，一条命令装好，升级是从当前服务器地址自举重装；地址三级解析（命令行 > 登录时存的配置 > 构建期内置），同一个包既能指外网也能指内网。
规模与口径：512 MB 单包上限 · 8 个 AI 辅助动作 · 试用上下文 150 KB / 实测双跑 64 KB · 试用限流 60 次/小时（匿名 10 次/小时/IP）· 合集包最多 200 个 Skill · 令牌 32 字节随机、只存哈希，管理员关掉"允许使用 CLI"即刻全部失效

功能亮点 用户看到什么

  • 贴个链接就入库。公众号 / 博客链接，或上传 PDF、EPUB、PPT、Word，几秒出正文、封面、作者和预计阅读时长；重复提交自动识别是同一份。
  • AI 先通读：整体导读（概述 / 脉络 / 要点 / 值得问的问题）+ 逐章摘要，中英双语，结果全站共享 —— 第二个人打开不再花一分钱模型调用。
  • 问文档，答案带原文出处。每句结论后跟一个可点角标，点一下跳回原文并高亮，能立刻验证 AI 有没有编。
  • 划线、批注、共享笔记。打开"公开我的笔记"后，同事读同一篇能看到你的划线，还能针对某条划线开讨论。
  • 选中即译（中英互译）· 读到第几章自动记住 · 书架、评分、评论。

技术亮点 工程上难在哪

  • 五种格式收敛成一套坐标系。网页 / PDF / EPUB / PPT / Word 各有抽取器，但都产出同一结构：净化后的章节 HTML + 纯文本 + 检索片段，并强制"片段文本必须等于章节文本的这一段"这条不变式 —— 正是它让 AI 的引用和用户手划的线落在同一个偏移空间里，能互相跳转。扫描件和字体映射损坏的 PDF 主动识别并降级提示看原文，不把乱码喂给 AI。
  • 逐章 AI 索引：断点续跑 + 抢锁 + 成本封顶。结果直接写在章节行上当检查点，失败或重启只补没做的章；并发用一次原子更新抢锁、配 10 分钟过期防死锁；单篇最多索引 120 章封住成本。中文结果先落库再跑英文翻译 —— 翻译途中被重启不能把已跑完的中文一起丢掉。
  • 没有向量库，就用两阶段检索。第一阶段只让模型看"每章摘要 + 关键词"这份索引，选出候选章并给出会在原文里字面出现的检索词；第二阶段用这些词做数据库匹配。引用信息随流式响应的第一帧下发 —— 放响应头会撑爆 nginx 的缓冲区上限。
  • 抓公网的安全边界：链接抓取做 SSRF 防护并对每一跳重定向重新校验（只在内网部署放行内网地址）；EPUB 解压对单个条目卡上限防压缩炸弹；公众号图片会被重新托管到本地，否则防盗链让图全裂。
规模与口径：6 种入库来源 · 单篇最多 120 章 · 检索片段目标 500 token / 硬上限 800 · 单次问答上下文 10,000 token · 每人每篇最多 500 条划线 · 抓取总预算 90 秒、最多 5 次重定向 · 27 个前台 API 路由 · 阅读器 145 条三语文案
这个模块的含金量在"AI 说的话能被一键核实"：引用不是装饰，是能点开跳回原文的坐标。

技术亮点 工程上难在哪

  • 两套翻页游标，按排序方式分流。"最新"用显式键集游标（把上一条的时间+id 编进游标）；刻意没用框架自带游标 —— 那条帖子被删或被置顶后它会静默翻错页。"热门"排序会随点赞实时漂移，没有稳定锚点，就退化成偏移游标，用简单换正确。
  • 反应计数的语义边界。一人一帖只有一行记录，总赞数是所有表情之和，所以"从赞切换成有启发"只改那一行、完全不碰计数器；只有新增和取消才走事务同时改行和计数。并发冲突时整体回滚并返回权威真值，用户永远看不到报错，数字也不漂。
  • 墓碑删除 + 守卫式事务。有回复的评论删成墓碑保住楼层结构；判断不能只靠事务外的预读，而是把条件直接写进更新语句的 WHERE，匹配不到就整体放弃 —— "两个人同时删"和"删的瞬间来了新回复"都不会把计数改花。论坛还多一步：删回复后从剩余回复重算最后活跃时间，堵住"回一条再自删把话题永久顶上去"。
  • 附件的四道信任链。只认存储 key、地址服务端重新推导、正则限死前缀再做路径穿越校验，再加一条：已经被别的帖子引用过的 key 直接拒绝（key 在地址里肉眼可见，否则能把别人的文件挂到自己名下）；删帖回收磁盘按引用计数走。
  • 中文文件名不能进响应头 —— 超出 ByteString 范围会让下载接口直接 500。这里按 RFC 双写：ASCII 兜底 + 百分号编码的真名。
规模与口径：10 张数据表 · 16 个 API 路由 · 3 次结构演进 · 单视频 1 GB / 单文档 100 MB / 每人每天 5 GB 上传预算 · 8 个主题分类（每话题最多 3 个）· 摘要按码位截断 140 字（不切断表情和生僻字）

  • 票数不是累加出来的，是每次从选票明细重算的。投票在一个 Serializable 事务里完成：写选票 → 从明细重算这个作品的票数 → 重算活动总票数和参与人数。改票、撤票、并发投票都不可能让票数对不上。每一票都要改同一行活动记录，高并发下必然冲突，所以配了带抖动的退避重试（最多 5 次），而不是硬撞。
  • 预算与上限在事务里判定。"每人 10 票""单作品最多 1 票"这类规则如果在事务外查，两个标签页同时点就能超发；这里是进事务后重新统计已用票数再决定。按天发票的桶用北京时间的日期做键，跨时区不会串天。
  • 刷票的三道门：内网部署下投票强制要求 W3 实名身份（密码注册的小号直接拒绝）；一人一作品一天只有一行记录，物理上无法重复；下架的作品不再接受新票，但撤票永远可用——否则你的票会被永久占住。

  • 导出的 CSV 带 BOM（Excel 打开中文不乱码），并对以 = + - @ 开头的用户文本加引号前缀，防止表格公式注入；排名用并列名次算法，和页面上看到的完全一致。

  • 新人第一条帖打标，进管理员和种子用户的"待欢迎"列表，承诺 24 小时内有人回。
  • 发完给正反馈：多少人看了、谁点了反应、被谁转到了哪个话题。

技术：怎么做的 复用现有编辑器与 AI 管线

  • 编辑器不重做。模板只是给现有富文本编辑器灌初始内容 + 预挂话题，图片、视频、文件、表情包、投票这些能力已经在里面了。
  • AI 顺稿是服务端调用、结构化返回。沿用仓库里已经踩过坑的那套：思考型模型的思考块要过滤、JSON 提取要能处理截断和代码块，返回失败就静默降级成"不改"，绝不把半截内容写进正文。
  • 永不自动写入。AI 的结果放在对照面板里，用户点"采用"才进正文 —— 这是全站 AI 的统一红线：只建议、不落笔、可撤销。
  • "待欢迎"是一条 SQL 查询（首帖 + 无回复 + 超过 N 小时），不需要新表；欢迎回帖到位后自动出列表。
  • 阅读数按天去重，复用讨论区已有的浏览统计口径，匿名用户按代理链最后一跳记 —— 第一跳可伪造，这个坑仓库里已经踩过。
一句话：把"发"的成本压到一分钟，把"发完没人理"的概率压到零。这两件事做成了，社区就活了一半。

【新功能 11】语义搜索地基：一次投入，五个地方受益
这是全部规划里唯一一个有硬外部依赖的项目

技术：怎么做的 唯一的外部依赖

  • 全站内容统一向量化，存进数据库的向量扩展；写入时更新，存量夜间限速回填。
  • 可见性快照跟着向量走：内容转为私有时同步清除向量，检索结果再按查询者权限过滤一次 —— 双保险，因为搜索是最容易漏权限的地方。
  • 只提示不拦截。查重结果只是编辑框旁边的提示，永不阻止发布；阈值先灰度再放开。
  • 硬依赖：内网 vLLM 上加载一个 embedding 模型（bge-m3 / Qwen3-Embedding 级别，约 0.5–1B，单卡 8–16G 显存就够）。模型不大，但排期不由我们决定 —— 这是需要提前排队的一件事。
  • 排不上也有降级路径：先用大模型分组做缺口聚类、用现有关键词搜索兜底，功能打折但不阻塞。
不先做它，问答 AI、话题、专家匹配都只能跑降级版 —— 所以它要早排队，不一定要早上线。

【新功能 12】加分项：MCP 知识出口 + 双周挑战赛
一个是别家做不了的技术故事，一个是激活潜水用户最省钱的一招
