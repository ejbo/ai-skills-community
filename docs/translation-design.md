PLAIN VERDICT ON THE REASONING LLM ALREADY DEPLOYED: as a stop-gap, yes — with `enable_thinking=false` it translates acceptably (the design ships on it first). As the X-style 'translate this post' engine, no, for three reasons the codebase already demonstrates: (1) quality — non-thinking general models score 49–54 XCOMET on WMT25 vs 62–64 for Hy-MT2 (Qwen3-32B only 0.36 in the HY-MT1.5 table); thinking narrows the gap a few points and on informal text HURTS (DeepSeek-V3.2 instruct 81.3% MQM≥80 vs thinking 76.3%); (2) latency/cost — reasoning models emit ~500–1000 chain-of-thought tokens per snippet (DeepSeek-R1 avg 485), turning a 0.4 s translation into 10–30 s and burning the shared `LLM_MAX_CONCURRENT=6` queue that 知识库 chat/indexing use; (3) reliability — every existing translation failure in this repo traces to `<think>` truncation and JSON parsing (`extractJsonObject`, `stripThinkDeltas`; `complete()` does not even strip `<think>` from plain-text replies), while a dedicated MT model returns plain text. A dedicated model costs ~8 GB of VRAM and one systemd unit; it is worth it and it is what makes 'fast' true. Keep the reasoning model for 知识库 summaries/QA; give Hy-MT2-7B its own provider slot and pool, and repoint 字幕 cue translation and 知识库 全文翻译 at it afterwards so the whole site has one translation quality.

## 2. 视频翻译现状与可复用性

WHAT THE APP DOES TODAY: 'video translation' means ONLY subtitles on 随刷短视频 (shorts), and it is speech-to-text plus machine translation of the transcript — nothing else on a video is translated. Titles, captions (`Video.summary`), descriptions and comments are stored in one language and shown as-is to every viewer. The commit remembered as 'video bilingual titles' (4897f5d, 2026-08-13) added NO titleEn/descriptionEn on Video (verified: prisma/schema.prisma Video has only `subtitleStatus/SrcLang/ZhKey/ZhUrl/EnKey/EnUrl/Error/At` plus a nullable, unused `language`); its 'bilingual' half is the 知识库 (summaryEn / abstractMdEn / aiOverviewEn / aiSummaryEn + lib/library/i18n-content.ts pickText). The shorts pipeline (lib/video/subtitles.ts) runs in the background after a member publishes (`void generateShortSubtitles(id)` in app/api/shorts/route.ts) or on 生成字幕 (POST /api/shorts/[id]/subtitles): (1) atomic claim of the Video row (`subtitleStatus → processing` via guarded updateMany) with a 2-min lease renewal + stale sweep so a restart never leaves it stuck; (2) in-process FIFO (SUBTITLE_CONCURRENCY=1) because whisper is minutes of CPU; (3) ffmpeg → 16 kHz mono wav; (4) a LOCAL whisper (whisper.cpp or openai-whisper, auto-discovered binary + ggml model) → WebVTT; (5) CJK-ratio heuristic decides 中文 vs English; (6) the house LLM (same admin-configured 知识库 model via getLibraryProvider) translates the cues into the other language 30 per call with a numbered-list prompt ('编号. 译文') and DROPS THE WHOLE TRACK on any line-count mismatch (no cache, no JSON gate, and exposed to `<think>` leakage because `provider.complete()` never strips it); (7) both VTTs saved as subtitle/<id>.vtt, URLs on subtitleZhUrl/EnUrl; the player (ShortsCell) cycles 关→中→EN, defaulting to the viewer's UI locale, drawing the cue as its own overlay. Failures land on subtitleError and never break the upload.

CAN THE SAME METHOD BE USED FOR POSTS/COMMENTS? Partly. WHAT TRANSFERS: the fire-and-forget trigger right after a write (the `void notifyX(...)`/`void generateShortSubtitles` position), the language-detection heuristic, the shared LLM provider layer (queue, timeouts, DIRECT egress via llmFetch, admin override), the 'status/error on the row, never on the request path' discipline, and — only if a durable queue is ever needed — the atomic claim + lease + stale-sweep shape. WHAT DOES NOT TRANSFER: whisper/ffmpeg (audio-only); the numbered-list prompt (fragile: no cache, count mismatch loses everything, no reasoning-tag stripping — the 知识库's index-keyed JSON batch in lib/library/ai-prompts.ts is the better base); the fixed *Zh/*En twin-column shape (pre-translating into two columns per table cannot serve a French reader, does not scale to the ~20 content tables, and is the YouTube-style 'silently replaced' shape rather than X's 'translate on demand, show original'); and the batch/offline timing (a short is translated minutes after upload while whisper runs — a comment must translate in under a second on click). THE CLOSER PRECEDENT IS THE 知识库: lib/library/translation.ts already does per-passage translation cached by (targetLang, sha256 of whitespace-normalized source) on `LibraryTranslation`, POST /api/library/translate is cache-first and only rate-limits misses, and the reader has a 原文/译文 toggle — that, with the `docId` scope removed, `fr` added, markdown-aware block splitting, and the 翻译 link put under every post/comment, IS the X-style mechanism. Once it ships, the subtitle cue translator is repointed at the same engine (one cue = one passage, index-keyed, per-cue guards) so a failed cue keeps its original line instead of dropping the track, and 字幕 quality follows the dedicated MT model for free.

## 3. 设计：翻译 — X-style on-demand in-site translation on a global hash cache, served by a dedicated Hy-MT2 slot (Angle A spine + graded grafts from B/C)

### 3.1 Thesis

All paths relative to /Users/jzl19991121/Projects/skills-community. Ship the X/Twitter affordance, not a translation platform: every post, comment, reply, caption and 作品评论 whose detected language differs from the viewer's locale grows a quiet ink text link 「翻译」; a click hits ONE cache-first endpoint (`POST /api/translate {kind,id}`) that loads the source SERVER-side, re-runs the surface's own read gate ('translatable exactly when readable' — the comment-like rule), splits the markdown into translatable blocks with every opaque token protected, translates only the cache misses through a dedicated non-reasoning MT slot (Hy-MT2-7B) with mechanical output guards, and returns assembled markdown that the SAME `MarkdownRenderer`/`ZoneMarkdown` renders in place under a one-line attribution 「译自中文 · Hy-MT2 · 显示原文」. Translations are viewer-side render state backed by a shared hash cache — never written into content, never broadcast (Slack/Mastodon model). The whole thing is the existing 知识库 selection-translate pipeline (`lib/library/translation.ts` + `app/api/library/translate/route.ts`) with the `docId` scope removed and `fr` added: one migration, one route, one client component, one i18n namespace, the provider slot as extra columns on the existing `LibrarySetting` row. No job table, no worker, no cron, no `lang` columns on content tables — legacy rows work on day one with nothing to backfill. Pre-translation exists only as a write-time cache WARM for the P0 kinds (fire-and-forget, cache row as checkpoint) so the opt-in 自动翻译 mode feels like X; the durable outbox (Angle B) is deliberately NOT built — losing a queued warm on restart costs the first reader ~1 s. From Angle C we graft what is pure and cheap: the format-fidelity self-test that picks the placeholder style on the REAL model before content code depends on it, the output guards (echo/language/length/emphasis), a per-run deadline, route-by-shape to the JSON path, a protected-term list, an item-level cache row so auto mode paints at SSR, and a 翻译有误 feedback hook. From Angle B: `hasTranslatableText`, the JSON prompt's `src` field, anonymous cache-hits-only on public kinds, an outage-only fallback to the house LLM behind a default-OFF toggle, the kill switch, the thinking-on admin banner, and the honest cost model in docs/capacity-tuning.md. Speed target: cached item <50 ms; uncached comment ≈0.5–1 s on Hy-MT2; uncached 3k-char topic ≈2–4 s (blocks fan out in parallel).

### 3.2 Model wiring

DEPLOY Hy-MT2-7B-FP8 as a second vLLM process (see modelRecommendation for sizing, flags, verification). WIRING — a new provider slot `lib/translate/provider.ts` `getTranslationProvider(): Promise<{ provider: LLMProvider; kind: 'mt'|'general'; label: string; isLibraryFallback: boolean }>` cloned from `lib/library/llm.ts` (60 s module cache + `bustTranslationLlmCache()`), built ONLY through `OpenAiProvider({ ..., fetchImpl: llmFetch, pool: 'translate', extraBody })` (DIRECT egress via lib/llm/egress.ts; never a bare fetch). Resolution order: (1) admin override = new columns on the existing `LibrarySetting` row (`translateLlmProvider/BaseUrl/ApiKey/Model`, `translateLlmKind`, `translateEngineLabel`, `translateExtraBody`, `translateEnabled`, `translateFallbackToLibrary`, `translateWarmOnWrite`) edited by `app/manage/library/TranslateSettingsCard.tsx` (Chinese — /manage rule) via `PUT /api/admin/library/translate-settings` (`gateApi('library')`, `__keep__` API-key sentinel, `logAdmin`); (2) env `TRANSLATE_LLM_BASE_URL / TRANSLATE_LLM_MODEL / TRANSLATE_LLM_API_KEY / TRANSLATE_LLM_KIND` in `lib/env.ts` (restart, no rebuild); (3) FALLBACK `getLibraryProvider()` with `kind:'general'` — the house reasoning model, acceptable only with 关闭思考 on; the card shows a LOUD banner when the resolved provider is the library one and `llmDisableThinking` is false (this single misconfiguration turns 0.5 s into 10–30 s and dumps CoT tokens on the 知识库 queue). SAMPLING: rely on vLLM's `--generation-config auto` (Hy-MT2's repo ships T 0.7 / top_p 0.6 / top_k 20 / rep 1.05); add only an opt-in `extraBody?: Record<string, unknown>` to `OpenAiProviderOptions` (same self-hosted-only wire-flag family as `disableThinking`; api.openai.com would 400 on `top_k`) — no `temperature` threading through `LLMCompleteOptions` (verified: no provider sends one today). CONCURRENCY: `lib/llm/limits.ts` gains keyed pools — `acquireLlmSlot(pool = 'default', signal)`; pool `translate` = `TRANSLATE_MAX_CONCURRENT` (default 8), so a burst of 翻译 clicks never shares the 6 slots with 知识库 chat and vice versa; when the resolved provider is the library fallback the engine caps the translate pool at `TRANSLATE_FALLBACK_CONCURRENT` (default 2) because it is the same GPU. Per-run deadline `TRANSLATE_RUN_TIMEOUT_MS` (default 20 000) via `signal: AbortSignal.timeout(...)` — never the inherited 300 s `LLM_COMPLETE_TIMEOUT_MS`. TWO PROMPT SHAPES chosen in `lib/translate/engine.ts`: `mt` → ONE block per call, plain text, the official Hy-MT2 prompt ('Translate the following text into {Simplified Chinese|English|French}. Note that you should only output the translated result without any additional explanation.') + 'Keep every ⟦n⟧ marker exactly as written, same count and order; do not translate, remove or add markers. Keep Markdown markers (#, -, >, |, *, **) as they are.' + a terminology line with the ≤12 glossary pairs present in the block; blocks of one item dispatched concurrently under the pool (vLLM batches them server-side). `general` → the existing 12-passage index-keyed JSON prompt, `translatePassagesPrompt`/`parseTranslatedPassages` MOVED to `lib/translate/prompts.ts` (generalized to `targetLang: 'zh'|'en'|'fr'`, placeholder rule appended, asks for a top-level `"src": "zh|en|fr"`), re-exported from `lib/library/ai-prompts.ts` so the library keeps working; `json: true`, NO `maxTokens` (house rule), parsed by `extractJsonObject`. ROUTE BY SHAPE even when an `mt` slot exists: a block with >40 placeholders or >1500 chars, or a table row with >8 cells, goes to the `general` JSON path (instruction-heavy runs are where a plain MT prompt fails); a block that failed guards on `mt` is retried once with the strict suffix ('Output only the translation, keep every ⟦n⟧ marker.'), then sent to the JSON path if a general provider is configured, then kept original (`partial`). REASONING LEAKAGE: factor `stripReasoning(text)` out of `extractJsonObject` (`lib/llm/sse.ts` or `lib/skill-assist.ts`) — 'everything after the LAST closing reasoning tag, null on an unterminated opener' — and run every plain-text reply through it before guards, so a mis-pointed reasoning model on the mt slot degrades to 'kept original', never to leaked chain-of-thought. WHEN TO FALL BACK TO THE HOUSE LLM: (a) nothing configured — automatic, with the banner; (b) `translateFallbackToLibrary` (default OFF on the intranet) — ONLY on `LLMNetworkError`/5xx three times in a row (a rebooted GPU box), NEVER on parse/placeholder failures (those are prompt problems, not outages) — because auto-fallback silently moves MT load onto the reasoning model exactly when it is least wanted; (c) the JSON path for shape-routed/failed blocks above. Auto-translate mode and warm-on-write are DISABLED by the engine when `kind === 'general'`. ATTRIBUTION HONESTY: `translateEngineLabel` defaults to the served model id and the card warns when the label diverges from `translateLlmModel`.

### 3.3 Architecture

MODULES (new, under `lib/translate/`; ★ = import-free, client-safe):
★ `shared.ts` — `ContentLang = 'zh'|'en'|'fr'`, `CONTENT_LANGS`, `viewerLang(locale)` (zh-CN→zh, en→en, fr→fr — deliberately NOT `lib/library/i18n-content.ts#contentLocale`, which folds fr into en for the library's stored twins), `TRANSLATE_KINDS` catalog with per-kind `fields: {name, format:'md'|'plain'|'title'}[]` and `public: boolean` (anonymous-readable kinds), `PLACEHOLDER_STYLE` (single constant, default ⟦n⟧ U+27E6/U+27E7 — see markdownHandling), limits `MAX_BLOCK_CHARS 1500`, `MAX_ITEM_CHARS 24_000` (topics ≤20k fit; zone posts/wiki/skill README beyond it → 413 until the later background pass), `TranslationView { state:'ready'|'partial'; fields:{body?,title?}; sourceLang; targetLang; engine; coverage }`, `normalizeSource`/`sourceHash`/`fnv1a` (sha256 moved here from `lib/library/translation.ts`, re-exported there).
★ `detect.ts` — `detectContentLang`, `hasTranslatableText`, `looksLikeLang`.
★ `markdown.ts` — `splitTranslatableBlocks(text, format)`, `protect/restore`, `assemble` (pure; tests/translate-markdown.test.ts).
★ `guards.ts` — `checkBlock(source, output, slots, pair) → {ok, reason}` (pure; tests/translate-guards.test.ts).

`sources.ts` — the KIND REGISTRY: `TRANSLATE_SOURCES[kind] = { load(id, viewer) → { fields, editedAt } | null }` where each loader re-runs the surface's OWN read gate by importing the SAME helper its LIST route uses and returns null ⇒ 404: `post` (Post.bodyMd, deletedAt null), `post_comment` (PostComment.bodyMd, not tombstoned), `topic` (title + bodyMd), `topic_reply`, `video_comment` (VideoComment via `canViewVideo` on its video — isShort decided by the read), `short_caption` (Video.summary/title where isShort && PUBLISHED_PUBLIC), `vote_comment` (VoteComment.body — activity published, entry `hidden:false && status:'approved'` unless `domainViewer(user,'votes').canManage`, comment ∈ entry ∈ activity). A test asserts every `TRANSLATE_KINDS` key has a loader.
`service.ts` — `translateItem({ kind, id, viewer, target }) → TranslateResult`: load+gate → `hasTranslatableText` → `detectContentLang` (=== target ⇒ `{same:true}`) → item-cache hit with matching full-field `sourceHash` ⇒ return → split → dedupe blocks → block-cache lookup → `translateBlocks` on misses → assemble → `putItem` (state ready if coverage=1 else partial) → return. Whole-item budget `TRANSLATE_ITEM_TIMEOUT_MS` 45 s: past it, return what is assembled as `partial` and let the rest finish `void` so a re-click completes.

`lib/llm/limits.ts` — keyed pools. `lib/llm/openai.ts` — `pool` + `extraBody` options.

DATA FLOW (on demand — the only path in increments 1–4): `Translatable` client leaf → `POST /api/translate` → registry load + gate → item cache → block cache (one `findMany`) → misses to the model → `createMany` → assembled markdown → client swaps the `content` prop of the EXISTING renderer and shows the attribution line. Nothing is written to content tables. Lists/excerpts (`excerptOf`, 社区此刻, search) stay in the source language (X translates items, not indexes) until increment 8.

ON-DEMAND vs PRE-TRANSLATE — the honest split: (1) comments/replies/captions/posts: on demand; one MT call ≈0.5 s; every later reader in any language pays nothing. (2) 自动翻译 (increment 5): RSC list/detail loaders call `getItemsForList(kind, refIds, target)` ONCE per page and attach a cached `TranslationView` where the viewer has `autoTranslate`, detected lang ≠ viewer lang and ∉ `translateSkipLangs` — so cached items paint TRANSLATED AT SSR (no flash of original); uncached items render the original and register with a shared IntersectionObserver that coalesces viewport entries (150 ms) into `POST /api/translate/batch` (≤30 items; first viewer of a fresh post waits ~1 s). (3) Write-time WARM (increment 4): `void import('@/lib/translate/warm').then(m => m.warmItem(kind, id))` (the `triggerIndexing` pattern) after a successful create/edit of a P0 item — the only 'pre-translation'; stores nothing on the content row; best-effort. (4) Long bodies (zone posts/wiki up to 200k, skill README): 413 `too_long`; a translate-doc-style background pass with a `translationState` is a separate, optional follow-up.

BACKGROUND JOBS: none required. Warm is fire-and-forget in-process (single Node process — docs/capacity-tuning.md; the cache row is the checkpoint, a restart loses only in-flight warms, nothing is claimed so no lease/sweep). Scripts in the `scripts/backfill-*.ts` style: `scripts/translate-probe.ts` (raw-endpoint fidelity/latency probe used by ops before any app code), `scripts/warm-translations.ts` (`pnpm translate:warm --days 30 --kind post,post_comment`, off-hours), `scripts/prune-translations.ts` (orphan item rows + never-re-hit block rows >180 d; cron twin like send-event-reminders.ts). If multi-process (capacity-tuning appendix C) ever ships and warming needs durability, the outbox + guarded-updateMany claim/lease from lib/video/subtitles.ts is the port — not built up front.

HEALTH: `GET /api/admin/library/translate-health` (`gateApi('library')`) reports MT reachability (real 1-sentence completion, latency, route/errno via `LLMNetworkError`), pool depth, in-process `hit/miss/mtCalls/llmCalls/guardFail{reason}` counters, and the FORMAT-FIDELITY SELF-TEST (fixture: 10 placeholders + a link + a protected term + a `[poll:xxxxxxxx]` line; reports survival %). This is how the placeholder style is validated on the real model rather than assumed.

VIDEO/LIBRARY PARITY (increment 7): `lib/video/subtitles.ts#translateCues` and `lib/library/translation.ts#translateWithCache` repoint at `getTranslationProvider()` + `translateBlocks` (cue = one passage, index-keyed, per-cue guards — a failed cue keeps its original line instead of dropping the track); `detectLanguage`/`detectSubtitleLang` delegate to `detectContentLang` (unify the 0.12/0.15 CJK thresholds on one exported constant). `LibraryTranslation` stays doc-scoped for the selection endpoint (it accepts client text) — not migrated in this design.

### 3.4 Schema

Migration `prisma/migrations/20260901000000_content_translation/migration.sql` (committed SQL; `pnpm prisma migrate deploy` on the box; local dev per memory uses `db:push`). Everything the later increments need ships in this ONE migration so P0→auto mode needs no second one.

```prisma
// Global block-level cache — the community pays once per passage.
// No item in the key: cannot be enumerated per item; the read gate lives in the registry loader.
model ContentTranslation {
  id         String   @id @default(cuid())
  targetLang String   // 'zh' | 'en' | 'fr'
  sourceHash String   // sha256(normalizeSource(raw block)) — hash of the RAW block, placeholders NOT substituted
  sourceText String   // ≤ 1500 chars, kept for audit/rebuild (same as LibraryTranslation)
  text       String   // translated block, placeholders already restored
  engine     String   // 'mt' | 'general'
  model      String   // served model id — attribution + purge-by-model
  createdAt  DateTime @default(now())
  @@unique([targetLang, sourceHash])
  @@index([model])
  @@index([createdAt])
}

// Assembled per-item translation — ONE findMany per RSC page in auto mode; staleness by full-field hash.
model ContentTranslationItem {
  id         String   @id @default(cuid())
  kind       String   // TRANSLATE_KINDS key
  refId      String
  field      String   // 'bodyMd' | 'title' | 'summary' | 'body'
  targetLang String
  sourceLang String?  // detected / model-reported ('src'); null = unknown
  sourceHash String   // sha256 of the FULL field text at translate time
  text       String
  state      String   // 'ready' | 'partial'
  engine     String   // 'mt' | 'general' | 'mixed'
```

### 3.5 API

All routes `runtime='nodejs'`, `dynamic='force-dynamic'`, errors `{error:'<api_errors key>'}`.

`POST /api/translate` — body (zod) `{ kind: TranslateKind, id: string, target?: 'zh'|'en'|'fr' }`; `target` defaults to `viewerLang(await getLocale())`. Steps (mirroring app/api/library/translate/route.ts): (1) `auth()`; anonymous is admitted ONLY for kinds with `public:true` (讨论区/意见反馈/活动/公告) and ONLY for cache hits — a miss returns `202 {status:'pending'}` with NO model call (anonymous traffic can never spend GPU); everything else 401 → client does the house login toast + `currentLoginHref()` redirect like `CommentLikeButton`; (2) registry `load(id, viewer)` with `viewer = domainViewer(session.user, <kind's domain>)` where a manager flag matters ⇒ null → 404 `not_found` (mirrors the kind's LIST route exactly; never accept client-supplied text); (3) total chars > `MAX_ITEM_CHARS` → 413 `translate_too_long`; (4) `!hasTranslatableText` → 200 `{ok:true, nothing:true}` (client hides the link); (5) `detectContentLang === target` → 200 `{ok:true, same:true, sourceLang}` (client hides the link); (6) item cache with matching `sourceHash`, else block cache — a FULL hit is answered BEFORE rate limiting and before touching the provider; (7) on a miss: `rateLimit('translate:'+userId, 120, 1h)` → 429 `translate_rate_limited`; `getTranslationProvider()` — `LLMConfigError` or `translateEnabled=false` → 503 `translate_unavailable`; (8) translate, save, assemble. Response `{ ok:true, target, sourceLang, fields:{ body?: string, title?: string }, state:'ready'|'partial', cached: boolean, engine: string, coverage: number }`; 502 `translate_failed` only when EVERY block failed (with a 200-char reason); `releaseRateLimit` refund on 5xx.

`POST /api/translate/batch` (increment 5) — `{ items: [{kind,id}] (≤30), target? }` → `{ ok, target, results: Record<'kind:id', TranslateResult | {error}> }`. Cache hits free; misses charge ONE unit each against the same `translate:<userId>` key; per-item failures never fail the batch; anonymous → cache hits only.

`GET /api/translate/status` — `{ available: boolean, engine: string|null, kind }` (60 s cached) — read once by `TranslatePrefsProvider` so the 翻译 link is hidden site-wide when no provider is configured or the kill switch is off (Mastodon capability flag) instead of rendering a dead button.

`POST /api/translate/feedback` (increment 5) — `{kind,id,field,target,verdict}` → upsert on the unique; `rateLimit('translate:feedback:'+userId, 60, 1h)`.

Settings: `GET/PUT /api/settings/translation` — zod partial `{ autoTranslate?: boolean, translateSkipLangs?: ContentLang[] }`, drop undefined, one `prisma.user.update` (the app/api/settings/privacy/route.ts pattern).

Admin (`gateApi('library')`, `logAdmin`, Chinese): `PUT /api/admin/library/translate-settings` (busts the slot cache); `POST /api/admin/library/translate-test` (real translation of a fixed zh+en+fr probe on the configured slot, raw error like llm-test); `GET /api/admin/library/translate-health` (see architecture); `POST /api/admin/library/translate-purge` `{ model }` → `DELETE FROM "ContentTranslation" WHERE model=$1` + matching item rows (confirm dialog; why `model` is stored and indexed); `GET /api/admin/library/translate-feedback?verdict=bad` (joins the item row so source/target show side by side).

GATES IN ONE SENTENCE: the registry loader is the gate and it MUST import the same helper the kind's LIST route uses (`canViewVideo`, the vote `hidden:false && status:'approved'` + published-or-manager rule, discussion `deletedAt:null`, later `canReadDoc`/`buildZoneAccess`+`decideZonePostAccess`), and every loader re-checks that the row belongs to the parent named in the kind — a `ContentTranslation` row is never addressable from a client by anything but passing that gate. RATE LIMITS: 120 misses/h/user on demand (hits uncharged); batch shares the key; feedback 60/h; warm-on-write has no user budget but is capped by `TRANSLATE_WARM_MAX_CHARS` 8000 and `TRANSLATE_PREWARM_SLOTS` 4, and runs only when the engine kind is `mt`.

### 3.7 Markdown handling

Principle carried over from `lib/library/translate-doc.ts`: model output is NEVER parsed as markup; it is substituted into slots we control, and any slot whose output fails validation keeps the original (partial coverage is fine). Implemented in the pure `lib/translate/markdown.ts` + `guards.ts`, pinned by `tests/translate-markdown.test.ts` / `tests/translate-guards.test.ts` with fixtures from real post shapes; mirror any change to `POLL_TOKEN_RE`/`EMBED_TOKEN_RE` here (the rule `tests/editor-embed-smoke.test.ts` enforces for the editor).

SEGMENTATION `splitTranslatableBlocks(text, format)`:
1. `format:'md'`: run `splitPollSegments` (lib/polls-shared.ts, fence-aware) then `splitEmbedSegments` (lib/zones/shared.ts) on every `md` segment — `[poll:<id>]` and `[embed:<kind>:<ref>]` lines become OPAQUE blocks emitted byte-identical and own-line (≤3 leading spaces preserved) so PollWidget/EmbedCard still mount and `collectEmbedRefs(translated) === collectEmbedRefs(original)`.
2. Inside each md segment walk lines with the same `FENCE_RE` (`/^ {0,3}(`{3,}|~{3,})/`) state: a fenced block (opener through matching closer or EOF, info string included) and indented code are one opaque block. Blank lines close a block; consecutive non-blank lines form ONE translatable block (a paragraph, heading, list, blockquote) — block granularity, not per-line, to keep cross-sentence context (fr pronoun agreement, zh→en topic continuity). Opaque: lines that are ONLY an image/sticker (`^\s*!\[[^\]]*\]\([^)]*\)\s*$`, `^\s*<img\b[^>]*>\s*$`, `<video …>`), a bare URL/autolink, an HTML-only line (`^\s*<[^>]+>\s*$` — `<details>`, `<br>`, table HTML), a table alignment row (`^\s*\|?\s*:?-{3,}`), `---`/`***`/setext underlines. Blocks > `MAX_BLOCK_CHARS` (1500) → sent to the JSON path (route-by-shape), > 6000 → opaque + `partial`.
3. GFM pipe tables: each ROW is a block; cells split on unescaped `|` are separate passages; alignment row opaque; a row whose cell count changed keeps the original row (>8 cells → JSON path).
4. `format:'plain'` (VoteComment.body, shorts caption, later noteText/bio): blocks = paragraphs split on blank lines with inner newlines preserved (`normalizeSource` collapses whitespace for the HASH only; stored `sourceText` and returned `text` keep the model's newlines); hashtags `#word` in captions protected. `format:'title'`: one block, output collapsed to one line.

PROTECTION inside a translatable block (`protect(block) → {text, slots[]}` / `restore(output, slots)`), placeholder = `PLACEHOLDER_STYLE` (one constant in shared.ts; default ⟦n⟧ U+27E6/U+27E7 with a decimal index — never occurs in real prose, and Hy-MT2's delimiter-preservation training is exactly 'copy N markers'; `{{n}}` was rejected because it collides with template-y content and needs an escape slot; the admin health self-test decides on the REAL model and `<x id="n"/>` (the HY-MT1.5 formatted-translation shape) can be swapped in without touching callers). Replaced, left-to-right: inline code `` `…` `` (longest-backtick-run aware), link/image destination `](…)` including title (link TEXT stays; image ALT stays), raw HTML tags `<…>` open and close with attributes intact (so `<a href>`/`<sup>`/`<br>`/`<mark>` survive), autolinks/bare URLs/emails, sticker/upload paths, footnote refs `[^1]`, `protected` glossary terms (CARI, W3, product names — case-insensitive word match), and any literal ⟦/⟧ in the source. Structural prefixes (`#{1,6} `, `- `/`* `/`1. `/`- [ ] `, `>` depth, leading `|`) are left IN the text (the prompt says keep them; the guard checks them). Emphasis `**`/`_`/`~~` left in place. A block that is only placeholders/whitespace/punctuation is copied through, not sent (`hasTranslatableText`).

GUARDS `checkBlock` on every reply from either engine, in order, each with a machine-readable reason counted on the health page: (0) `stripReasoning` + strip a trivially-wrapping quote pair or instruction echo ('Translate the following', 'Sure', '翻译：'); (a) placeholder identity — every ⟦n⟧ exactly once, none extra, paired link placeholders in order; (b) structural — the block's leading marker (heading level, list marker, `>` depth, leading `|` and cell count) present at the start of the output; (c) untranslated — normalized output == normalized input while source has ≥3 letters and source≠target ⇒ model echoed; (d) target-language re-detect `looksLikeLang(output, target)` for outputs ≥12 letters; (e) length ratio on non-placeholder chars — zh→en 1.3–5.0, en→zh 0.15–0.9, zh→fr 1.4–5.5, fr→zh 0.15–0.9, en↔fr 0.6–1.8, blocks <8 chars exempt; (f) emphasis balance — `**`/`~~` counts even, backtick count unchanged (should be 0), no fence opener introduced. Failure → retry once on `mt` with the strict suffix → JSON path (if a general provider is configured) → keep ORIGINAL block, `partial=true`.

CACHE KEY is the raw block text (hash of `normalizeSource(block)`), NOT the placeholder form — a plain passage and a markdown paragraph with identical words share a row, and the stored `text` is the restored translation, so `PLACEHOLDER_STYLE` can change without invalidating the cache.

ASSEMBLY `assemble` re-joins blocks with their original blank-line separators, restores placeholders by index, so the translated markdown renders through the UNCHANGED `MarkdownRenderer`/`ZoneMarkdown` — same sanitizer (lib/markdown.ts sanitizeSchema; even a model that emitted HTML can only produce what the schema allows), same poll/embed mounting, same sticker branch (`isStickerSrc` tests the raw stored src — unchanged bytes), same `withBasePath` for image src (URLs were never sent). Heading ids: ZoneMarkdown recomputes on content change; `PostToc` follows. Excerpts are never translated separately — a translated excerpt (increment 8) is `excerptOf(translatedBody)` through the same function. HTML (library chapters) keeps `htmlBlockTexts`/`applyBlockTranslations`; VTT cues: one cue = one block, timing lines untouched (increment 7).

TESTS to pin: round-trip identity when every block translates to itself; poll/embed/fence lines byte-identical incl. a `[poll:x]` INSIDE a fence staying inert; sticker/image/link-href/inline-code bytes survive while link text translates; placeholder missing/duplicated ⇒ original kept + partial; table alignment row opaque + cell count preserved; literal ⟦ in source round-trips; heading marker preserved; plain format preserves inner newlines; each guard reason on a fixture; `detectContentLang` on zh/en/fr samples and code-heavy comments.

### 3.8 Language detection

Pure heuristic, no model call, NO stored column (the one exception: `Video.language` stamped from the caption on shorts publish, because it already exists and the caption sits in a scroll-snap cell). `detectContentLang(text): 'zh'|'en'|'fr'|null` in the import-free `lib/translate/detect.ts`, run identically on the client (to decide whether to SHOW the link) and on the server (to short-circuit `same:true` and fill `sourceLang` in the attribution). Rules: strip fences, inline code, URLs, placeholders, `[poll:]`/`[embed:]` tokens, HTML tags and emoji first (a code-heavy 中文 comment must not read as English); sample the first 4000 chars; CJK share of letter-class chars ≥ 0.15 ⇒ `zh` (the lib/library/types.ts threshold; `detectSubtitleLang`'s 0.12 is unified onto one exported constant in increment 7); else on Latin text: `fr` when (French diacritics `[àâçéèêëîïôûùüÿœæ]` ≥ 2 hits AND ≥ 0.5% of letters) OR (≥3 hits from a 40-word French stopword list — le la les des du de est une un et pour avec dans sur pas que qui ce cette ces nous vous ils elles sont être avoir plus très aussi mais ou donc — that outnumber English stopword hits: the and is of to with that for you are); else Latin share ≥ 0.5 ⇒ `en`; else `null`. `hasTranslatableText`: after protection a block needs ≥2 letters or ≥1 CJK char, else no link, no call, no cache row (「+1」「👍」, a bare sticker or URL). `null` is first-class: the link is still offered (Hy-MT2 is any-to-any and needs no source tag); on the JSON path the prompt returns `"src"` and that is stored as `sourceLang`; on the `mt` path the attribution says 译自其他语言 (`labels.lang.unknown`). Viewer side: `viewerLang(locale)` maps the `locale` cookie 1:1 (`useLocale()` client / `getLocale()` server) — fr readers translate INTO French; the library's `contentLocale` fr→en fold is deliberately not reused. `translateSkipLangs` (「不翻译此语言」) applies on top. Known failure: short/mixed strings (an English reply quoting a 中文 term, accent-less French) — the server's `same:true` hides the link after one click, 「翻译有误 → wrong_source」 feedback finds bad detections, and because nothing is stored, a better heuristic fixes every item retroactively. A composer-side author-declared language pill (Bluesky/Mastodon) is a possible later refinement, not v1.

### 3.9 Caching & cost model

Cheapest first, every layer consulted BEFORE any budget is charged or provider touched:
(1) CLIENT — module-level `Map<'kind:id:target:fnv1a(field)', TranslateResult>` in `Translatable` (per tab; survives re-mounts across feed paging and drawer open/close; the field hash drops a stale entry after an in-place edit; single-flight per key).
(2) ITEM — `ContentTranslationItem(kind, refId, field, targetLang)` with `sourceHash` of the FULL field: a repeat click on any item is one `findUnique`; auto-mode RSC loaders read `getItemsForList(kind, refIds, target)` in ONE `findMany` per page (≤1 row per item, indexed) so cached items paint translated at SSR; staleness is lazy — on lookup a hash mismatch (the author edited) recomputes, and most blocks still hit tier 3, so an edited comma costs one block; a 60 s in-process LRU (≤2000 entries) absorbs re-renders. Rows are UPSERTed (unique key), never a lock.
(3) BLOCK — `ContentTranslation(targetLang, sourceHash)`, global, not doc-scoped (the library's `docId` key is what stopped reuse): one `findMany … IN (hashes)` per item, `createMany skipDuplicates` on save (two viewers racing on the same fresh comment both translate once and one insert wins — no locking, no in-flight dedupe in v1; bounded by the 120/h budget and only on a brand-new item). Identical sentences across items/kinds (「谢谢分享」 in 300 comments, a quoted paragraph, a subtitle cue, a reader selection) are one row. Safe to share because the ONLY way to read a row is through a kind gate that already proved the viewer can read the source; the endpoint never accepts client text (the library selection endpoint, which does, stays doc-scoped).
(4) WRITE-TIME WARM (increment 4) fills tiers 2–3 for the two other languages right after a P0 write (`translateWarmOnWrite`, `mt` kind only, ≤8000 chars, ≤4 pool slots) so auto mode is a pure cache read for everyone but the author.
INVALIDATION: never by content edit (hashes change); by MODEL — admin 「清空该模型译文」 deletes block + item rows by `model` (why it is stored/indexed); glossary change (increment 8) deletes item rows containing the affected term, block rows stay. Rows are small (a paragraph + its translation ≈ hundreds of bytes); at thousands of items/day this is tens of MB/year — `scripts/prune-translations.ts` (orphan item rows via `NOT EXISTS` per kind, block rows with `createdAt` > 180 d never re-hit) as a weekly cron twin. `sourceText` capped at 1500 chars.
COST MODEL (write into docs/capacity-tuning.md next to the warm toggle; assumptions stated so ops can re-plug): ~300 P0 writes/day on the intranet (200 comments @ ~60 tokens, 40 动态 @ ~400, 15 topics @ ~1500, 25 captions @ ~60, 20 作品评论 @ ~30) ≈ 60k source tokens; on demand at ~10% non-中文 readers clicking ~20% of what they see ≈ 0.02–0.1 units/write ≈ seconds of GPU per day; warm-on-write into both other languages ≈ 2× 70k output tokens ≈ 1–2 GPU-minutes/day on a 7B (≈3k tok/s) — unmeasurable; on the SHARED reasoning model with thinking OFF at ~30 tok/s ≈ 3% of one slot spread over the day; with thinking ON ×5–10 tokens and 10–30 s/call ⇒ 3–7 slot-hours/day and visible 知识库 queueing — the case the banner and the `general`-kind warm/auto lockout exist to prevent. Backfill of a 5M-char corpus ≈ 4M tokens ≈ 25–40 min on Hy-MT2-7B, ~18 h on the reasoning model — `scripts/warm-translations.ts` off-hours, newest first.

### 3.11 Risks

- Hy-MT2 on the box: the May-2026 card said 'build vLLM from source, transformers≥5.6' although HunYuanDenseV1 is listed; the intranet vLLM version and NVIDIA-vs-Ascend are unverified; two vLLM processes must split one card's VRAM (the existing one must give some up). Mitigation: increment 0 is a pure spike with a probe script; the app runs on the reasoning model (关闭思考) meanwhile; the MT model on another box is just a base URL.
- Placeholder discipline is the whole markdown-safety story and no benchmark tests it for any model. Mitigation: guards make a failure a kept-original block + `partial` (never corrupted markup); the fidelity self-test measures survival on the real model and `PLACEHOLDER_STYLE` is one constant; blocks with ≥1 failed placeholder retry then route to the JSON path; `guardFail{reason}` counters on the health page show a degrading model.
- Terminology is Hy-MT2's documented weak spot (43–54% term accuracy): 技术专区 may come out 'Technical Zone' in one comment and 'Tech Area' in the next. Mitigation: the code-level term list + protected proper nouns from increment 1; a real glossary owner + table only if 翻译有误 shows drift.
- Heuristic language detection misfires on short, mixed or code-heavy text and on accent-less French. Mitigation: `hasTranslatableText`, server `same:true` after one click, 不翻译{lang}, `wrong_source` feedback, no stored column so a heuristic fix is retroactive.
- Global hash cache + gated loader: correctness depends on EVERY registry loader mirroring its surface's LIST gate; a lax loader (forgetting `hidden:false && status:'approved'` on vote_comment, or a future tighter 匿名评选 rule) turns /api/translate into a side door. Mitigation: one gate test per kind that calls the list helper and the loader on the same fixtures; loaders import the surface's own helper; the cache is never queryable by item; the library selection endpoint (which accepts client text) stays doc-scoped.
- Context-free block translation: identical blocks share one row across items and a paragraph is translated without its neighbours; term consistency across a long topic is not guaranteed. Acceptable at X parity; the optional 'previous block as context' field is the lever.
- GPU/queue contention: the fallback provider shares the reasoning model's vLLM; warm/auto/backfill on it would starve 知识库 chat. Mitigation: separate `translate` pool (capped at 2 on the fallback), warm + auto disabled on `general`, backfill only via script off-hours, kill switch, the thinking-on banner, outage-only fallback default OFF.
- Model down: on-demand returns 503 and the link hides via /status; nothing queues or sticks; cache hits keep serving; recovery is automatic — but auto-mode readers see originals until it is back. Accepted (this is why there is no outbox).
- Single-process, in-memory rate limits and fire-and-forget warms: a restart drops queued warms (first reader pays ~1 s) and resets budgets; two concurrent viewers of one fresh item can double-translate it (bounded). If multi-process ships, port the subtitles claim/lease shape then, not now.
- UI regressions: a fourth text link beside 点赞/回复/删除 can wrap at 375px; onDark/reader tones must be used on the shorts caption, vote lightbox and 知识库 comments or the link is invisible half the time; translated bodies change height (PostCard's ResizeObserver clamp is fine; keep the shorts caption `line-clamp-2` and never translate inside a snap cell without reserved height); SSR renders the original and auto mode swaps post-hydration.
- Root layout adds one `user.findUnique` (two columns) per request for the prefs provider. Mitigation: select only those columns; fold into the existing session read if it becomes visible in traces.
- Licence/eval caveats: Hy-MT2 numbers are mostly Tencent's own (HardMTBench is the only independent set, zh↔en only); fr quality is inferred from FLORES averages; automatic metrics over-reward RL-trained MT (WMT25 humans ranked the Hunyuan-based system below Gemini). The 翻译有误 hook and purge-by-model exist to catch and undo a bad model early.
- Scope: attachments (PDF/PPT/Word), images with text, and >24k-char zone posts/wiki/skill READMEs are NOT covered (413 `too_long`); anonymous readers get cache hits only. Say so up front so 'translate everything the user uploads' is not read as a promise for day one.

  - 修正/精确化：Hy-MT2-7B (HunYuanDenseV1ForCausalLM, plain hunyuan_v1_dense config saved with transformers 4.57.6) is natively supported by any released vLLM >= 0.10.0 (July 2025), so a pip-installed vLLM loads it with `vllm serve tencent/Hy-MT2-7B` — the model card's "Build vLLM from source" is unpinned boilerplate, and a user has already loaded it on pip vLLM 0.21.0 (Hy-MT2 issue #11). ## 7. UX 规则（来自 X / LinkedIn / Reddit / Bluesky / Mastodon / Slack 等的调研）

- Decide WHETHER to show the affordance server-side from a stored source language: detect (or let the author declare) the language once at write time, store it on the row, and render the translate link only when it differs from the viewer's locale. LinkedIn moved detection to an async write-time pipeline for exactly this reason; Bluesky/Mastodon store an author-declared `langs`. Never run detection per render or per viewer.
- Default to per-item, tap-to-reveal ('See translation' as a small quiet text link directly under the body — Instagram/Facebook/LinkedIn/Slack). Ship an account-level auto mode as an opt-in second step, and make it per SOURCE language (Facebook's offer/always/never tri-state; X's gear 'Automatically translate <lang>' / 'Never translate <lang>').
- When a translation is shown, keep the original one click away with a consistent verb pair: 'See translation' ↔ 'See original' (Meta, LinkedIn, Slack, Mastodon). Auto-translated items must still carry 'Show original'. Never silently replace with no revert (YouTube titles is the anti-pattern).
- Put a one-line attribution ABOVE or directly below the translated body in muted small type: 'Translated from {lang} · {engine}' (Mastodon 'Translated from {lang} using {provider}', X 'Translated from Japanese · Translated by Grok'). Pair it with 'Show original' and a small gear that opens the per-language preference — that trio is the recognisable 'X effect'. The engine name is the honesty signal readers trust; for the intranet name the house model.
- Translate the item, not the page: post body, comment/reply bodies, quoted/embedded post bodies, poll option labels, media alt text/captions each get their own translation (Mastodon Translation entity correlates by id; X translates quoted posts inside a post). Never translate identity or handles, hashtags/@mentions, URLs, code, or tokens like [poll:…]/[embed:…] — LinkedIn explicitly protects hashtags and mentions before sending text to the translator.
- Translations are viewer-private, ephemeral render state — never written into the content, never broadcast (Slack: 'only visible to you, other people always see the original'; Discord bots that re-post translations are the cautionary tale). Cache them server-side keyed on (source-hash, target-lang) so the whole community pays once per passage (Mastodon PR #19218, LinkedIn's encrypted in-memory cache) — exactly what the site's LibraryTranslation table already does.
- Show a real loading state in place of the link ('Translating…' — Bluesky's menu cycles Translate → Translating… → Hide translation) and degrade gracefully: if the backend is unavailable return 404/503 and hide the affordance (Mastodon instance capability flag) rather than rendering a dead button.
- Offer a one-tap 'Don't translate <language>' / 'I know this language' escape on every translated item (LinkedIn, Facebook, X gear). Adding a language to 'Languages you know' is the natural place for this; it removes the prompt everywhere at once and is what users on X begged for when the master switch was missing.
- Collect quality feedback inline but cheaply: 'Rate this translation' as a tiny link (Facebook, LinkedIn's 5-point comprehension scale). On a small internal site a thumbs-down that logs the (source, target, model) tuple is enough to spot a bad model.
- Bidirectional participation: let a member write in their own language and have READERS see it translated (Reddit auto-translates into the community's pre-set language). For a zh/en/fr community this means the composer never asks the author to translate; the render side does it.
- Keep the chrome ink-monochrome: every product here uses plain text links and a hairline separator for the translation block — no coloured badges, no accent buttons. The only non-text element is a small 'Aa'/globe glyph before the link and a gear on the attribution line.

### 反模式

- Auto-replacing text with no per-item 'show original' (YouTube titles/descriptions): breaks recall, search and author intent; spawns 'anti-translate' extensions.
- Auto mode ON by default with no master off switch (X's Grok rollout, Apr 2026): the top complaint; users hunted through language settings and installed extensions to undo it.
- Replacing the original instead of offering both when the platform previously appended (X's first Grok iteration): readers who half-know the language lose the ability to check the machine.
- Translating on the client by shipping the user off-site (Bluesky's old 'open Google Translate in a new tab', LinkedIn/Discord extensions): kills reading flow and is impossible on an intranet with no public egress.
- Posting translations as new content (Discord auto-translate bots, Zapier→Slack flows): doubles every message, pollutes threads, confuses notifications; translations must be viewer-private render state.
- Translating everything on the page including names, handles, hashtags, code, URLs and structured tokens: LinkedIn had to add explicit entity protection; a naive pass would corrupt [poll:…]/[embed:…] and sticker/img markup.
- Detecting language per render or per viewer, or with a dual API call (LinkedIn's prototype bottleneck): detect once at write time, store it.
- Hiding the affordance entirely when the viewer cannot control it (Instagram: creators and viewers can't stop 'See translation' from appearing on Stories/bios): always give a per-language 'don't translate' escape.
- Forcing a rich, branded, coloured 'AI translate' button: every mature product uses a quiet text link and a one-line attribution; a blue sparkle button would violate the site's ink-chrome contract and reads as 'AI 风很浓'.
- Machine-translating stored HTML by re-parsing model output as markup: the reader-side pattern (and the site's own translate-doc.ts) writes translations as textContent into leaf blocks; never let the model emit tags.
